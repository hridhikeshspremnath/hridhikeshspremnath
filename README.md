## ⚡ What I'm Building

My current work sits around the intersection of:

**Software Engineering × Security × AI × Trust**

I'm especially interested in questions like:

* How do we know a software artifact can be trusted?
* How should workloads prove their identity inside CI/CD?
* How can policy be enforced before code reaches production?
* How can AI agents interact with real systems safely?
* How can decentralized systems establish trust without relying entirely on a central authority?

I don't just want software to **work**.

I want to understand **how it can fail, how it can be attacked, and how it can be made trustworthy.**

# 🔬 Research

## Open-Source Software Supply Chain Security

I have been researching how attacks propagate across the open-source software lifecycle:

```text
SOURCE
  ↓
DEPENDENCIES
  ↓
BUILD SYSTEM
  ↓
CI/CD
  ↓
ARTIFACT
  ↓
DISTRIBUTION
  ↓
END USER
```

Areas explored include:

* Malicious package detection
* Dependency attacks
* CI/CD compromise
* Build-system attacks
* Maintainer trust abuse
* Software provenance
* Unicode-based source attacks
* ML-assisted malicious-code detection

A major case study is **XZ Utils / CVE-2024-3094**, which demonstrates how maintainer trust, source-level manipulation, and build-system compromise can intersect in a sophisticated supply-chain attack.

> **The goal isn't just to detect malicious code. It's to understand where trust enters the software lifecycle — and how to enforce it.**
